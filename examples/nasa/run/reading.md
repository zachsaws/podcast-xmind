# NASA 如何把经验传给下一代工程师

Source coverage: full

来源：[Small Steps, Giant Leaps 第181期：Passing Down Knowledge](https://www.nasa.gov/podcasts/small-steps-giant-leaps/episode-181-passing-down-knowledge/)，2026-09-02；主持人 Andres Almeida，嘉宾 Heather Koehler。2026-10-16 读取了发布方从开场到片尾的完整文字稿；未听音频，发布方未提供逐句时间码，以下用段落编号定位。“full”只指这份发布方文字稿，不证明音频逐字完整。英文原稿，中文整理；嘉宾的经验与判断均未独立事实核验。

## 快速扫读

这期最实用的问题是：组织留住了一份文档，是否就留住了知识？Koehler 给出的经验涉及人、模型、标准和工作机会四种载体。

- **经验随工程师跨项目流动。** 模型可以重用，但必须适应新约束；旧项目的系统知识帮助人判断新设计。
- **新人需要参与真实任务。** 观察、反复操作、在指导下失败，与正式培训互补。资深专家在旁承担指导责任。
- **购买服务仍有学习路径。** 独立分析与仿真能让采购方了解供应商设计的边界，而不只收到一个交付结果。
- **标准必须把适用边界写出来。** 简单易用有利于普及，却不能替代数据基础。旧模型长期缺少新观测，是她谈到的具体问题。
- **管理者要移除信息障碍。** 提供工具、培训和专家接触机会，并让不同背景的人进入技术评估团队。

如果只读一节，先读“标准如何保留知识边界”；负责团队培养，可接着读“新人如何获得真实经验”。办公室照片和个人职业转折也保留在文末，它们提供了这次对谈的人物背景。

### 经验如何从一个项目进入另一个项目

主持人介绍，Heather Koehler 是 NASA 飞行力学技术专家，参与过航天飞机与 Artemis 的太空发射系统（SLS），也开发过与微流星体环境有关的技术标准。以上是节目中的人物介绍，并非本报告另行核实的履历。[U001](#u001)

Koehler 先解释经验为什么能流动。飞行力学工程师会反复做任务设计、建立仿真和模型，并分析项目生命周期的不同阶段。这个过程让人理解组成飞行系统的子系统与部件；为某个项目解决复杂问题时形成的工具和方法，可能成为另一个项目的近似解。工程师转岗时，也把这些经验带过去。[U002](#u002)

她用太阳帆 CubeSat 任务举例：制导、导航与控制算法里包含反作用控制推进器、导航传感器和星敏感器的模型。后续任务若使用相同传感器或相近尺寸的推进器，就可能重用模型以及对系统性能的认识。[U003](#u003) 但这需要适应新的约束和环境。她强调的是先前方法可成为起点，没有主张原模型不加修改就适用。[U004](#u004)

另一个例子是航天飞机到 Artemis。按她的说法，RS-25发动机、固体火箭助推器、芯级贮箱，以及发射日目标计算等软件流程，经过重用或升级进入了 SLS。[U005](#u005) 当年设计、开发和运行航天飞机的部分工程师仍参与 SLS 与 Orion；即使硬件相似，使用环境改变后，过去的经验仍有助于设计会议和评审判断。[U006](#u006)

### 新人如何获得文档之外的知识

主持人追问软技能能否迁移。Koehler 说，工程师一次次向总工程师和工作组讲技术方案，练习的是把风险、尚不理解的地方和解决方案传达给正确的受众。技术表达能力是在经历完整项目周期时反复形成的。[U007](#u007)

对于没有写下来的知识，她的判断是，人通过观察他人、亲手操作和重复实践学习得最好。[U008](#u008) 她回忆自己的导师：允许她在指导下尝试、失败，甚至再次失败；解释工具如何使用、设计怎样避免失效，也陪她参加技术会议。[U009](#u009)

这些交流还发生在会议耳语和走廊谈话里。内容既有技术，也有组织文化和与会者的特点。她认为，这帮助自己在没有正式权力时也能影响决策。这里保留的是个人经验判断，不能据此推出已经证实的通用培养效果。[U010](#u010)

在 SLS 等项目中，资深工程师与职业早期或中期工程师结对，让后者参与设计、开发、测试和带队，为更高层次的工作作准备。新人有真实任务，但身边有资深专家，并非独自承担整个产品责任。[U011](#u011) NESC（NASA 工程与安全中心）还让职业早期员工加入技术评估团队，在解决复杂问题的过程中学习。[U012](#u012)

### 购买商业服务，怎样仍然学到系统知识

这是与带教相邻、但值得独立保留的话题。Koehler 提到，NASA 与商业航天合作，有时买的是服务，并不负责设计系统。此时仍能通过独立分析、仿真和测试获得实际经验。[U013](#u013)

机制在于：分析人员需要在不同运行约束下建模具体硬件，因此能看到设计限制、需求解释的差别以及技术的新用法。这些认识留在工程师的经验中，后续任务还可使用。她没有在这段给出某个商业合作项目的量化成效，也没有说独立分析等同于参与原始设计。

### 正式材料与培训保留什么

正式途径包括网络研讨会、技术报告，内容覆盖基础知识、新技术、过去项目的经验，以及飞行异常或失败。她所在的 NESC 保存了专家研讨会的录像库。[U014](#u014)

团队还提供软件工具、工程流程、系统工程领导力等培训，邀请退休工程师讲历史经验，并通过专家访谈记录教训。材料形式包括最佳实践手册、技术简报、报告、指南和工作坊。[U015](#u015) 她说这些课程很多时候向公众开放，并在 NASA 网站提供；不能把“很多时候”改写成“全部课程公开”。[U016](#u016)

### 标准如何保留数据、假设与适用边界

谈到微流星体环境标准时，Koehler 首先提出，要知道标准给谁使用，以及他们怎样使用。[U017](#u017) 她回顾，设计者与运行人员此前依赖一个简单的数学模型描述空间环境风险，但其观测数据有限，几十年没有得到新输入更新。[U018](#u018)

旧模型简单，容易理解和采用，这解释了它为什么能普及；她同时强调，新标准必须以数据为基础。[U019](#u019) 还要确认模型与实际飞行的环境范围相关，理解模型及其数据的限制，并把不确定性、假设、何时能用和怎样使用写清楚。[U020](#u020) 这段话不能只压缩成“标准要持续更新”，因为真正影响工程判断的是数据基础和适用条件。

新模型吸收了多位专家在研究与飞行项目中收集、解释数据的经验，以及他们使用旧标准时发现的缺口。[U021](#u021) 团队也听取设计者和运行人员意见，确认他们实际需要的参数，并以易用格式提供。[U022](#u022) 因而，可采用性仍然重要，只是它需要与数据和边界说明同时成立。这里是对她论述的整理，并未额外检查标准的现行版本或有效性。

### 管理者怎样降低知识流动的阻力

她希望领导者明确愿景和目标，再给团队自主寻找执行方法的空间。[U023](#u023) 早期导师不保留数据、方法与实践诀窍，这使她既成为更好的工程师，也学习怎样领导；她现在试图延续这种分享方式。[U024](#u024)

她把信息可获得性与跨系统、跨组织集成联系起来。落实的动作包括提供飞行力学工具、技术培训，以及让专家能帮助他人改进设计。[U025](#u025) 她还特别提到，应有意识地组建具有不同视角和技能的专项团队或评估团队。[U026](#u026) 这比一句“建立知识共享文化”具体，但仍是嘉宾对自身管理做法的陈述，访谈没有提供前后对照数据。

### 照片、职业建议与她所说的转折

主持人注意到她办公室里的照片。Koehler 解释，那是从空间站拍摄的地球边缘与流星体进入大气的画面；离开原组织时，团队在照片上签了名。它既对应自己多年的研究环境，也保留了团队关系，因此对她有个人意义。[U027](#u027)

她给年轻工程师的建议是保持好奇、多问问题。按她的理解，提问会促成带教，带教形成关系，而这些关系会支撑职业发展。[U028](#u028) 她也鼓励求助、接触不同任务，并把失败和“知道什么行不通”当作经验的一部分。[U029](#u029)

问到自己的“巨大跨越”，她的回答是逐渐意识到：人际关系对自己的成功可能比某项技术成就更重要。这是带有“可能”限定的个人回顾，不是经过比较研究的结论。[U030](#u030) 接受自己不必什么都懂、愿意接受带教后，她获得了新的机会和经验。[U031](#u031)

她希望回报前辈的方式，是把所学继续传下去；在她看来，个人留下的价值也体现在投入时间培养过的人身上。[U032](#u032) 报告保留这段作为她的职业判断，不代替她把它扩展成更大的结论。
