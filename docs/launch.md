## Why this order

GitHub describes the README as the place to explain what a project does, why it is useful and how to get started. We therefore put an inspectable example before implementation details, and keep complete compatibility evidence in its own document. [GitHub: About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes).

Topics help people find repositories by purpose or community. Use relevant terms such as `agent-skills`, `podcast`, `codex` and `claude-code`; do not tag native XMind export as available. [GitHub: Repository topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).

GitHub recommends a solid, legible social image, ideally 1280×640 and below 1 MB. The image was uploaded under **Settings → Social preview**, and GitHub returned `usesCustomOpenGraphImage: true` on 2026-10-16. Future replacements should also be verified after saving; committing a file alone does not configure that field. [GitHub: Social previews](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview).

## A focused launch sequence

1. **Validate the first-use path.** Have a new user choose a host, install, supply rights-cleared material and open the result. Capture access failures as well as successes. Native Chat and live Claude Code acceptance remain explicit gaps.
2. **Share one concrete case.** Lead with the 1,000-registered/80-paying correction or the stable-input condition and failed pilot. Link the original and full reading so others can check it.
3. **Reach the right readers.** Start with agent-skill builders and people who already work through a podcast backlog. Follow each community's self-promotion and link-sharing rules. A submission is a separate action; none is sent by this document.
4. **Collect consequential omissions.** For the first small set of trials, prioritize a source span, actual output and the reason the missing detail matters. Use this to select the next improvement.
5. **Report only observed outcomes.** Record available repository traffic, actual installation reports and concrete feedback with dates. Compare Stars before and after distribution, but do not treat Stars as evidence of reading quality.
