# A useful open-source launch

Positioning: **Read the depth. Skip the filler.** The distinctive promise is
traceable retention and honest coverage boundaries, not another “podcast summary”.
Star growth is an outcome to observe; no number or rate is promised.

## Included in this release

- Chinese and English README with a short installation path and visible limits.
- Original visual explaining the source → ledger → reading → evidence flow.
- A small inspectable synthetic example, including the actual independent run.
- A real link-to-reading case with source provenance and a complete audit trail.
- MIT original implementation, standard-library helpers, CI and downloadable
  deterministic skill/plugin bundles with checksums.
- A concrete omission-reporting template and contribution rules.

The demo compares source details with this output. It is not a staged “competitor
failed” example. A comparison with another workflow would need the same sources,
declared prompts, model settings and independent evaluation before publication.

## Next distribution steps (not sent or scheduled)

1. Test installation from a clean account and collect the first actual reading
   feedback. Prioritize “what did it omit?” over general praise.
2. With rights-cleared material, add a short screen recording showing one link,
   source coverage, layered output and clicking a consequential claim to evidence.
   Keep failed source retrieval visible if that is what actually happens.
3. Publish a case write-up explaining the corrected number, denominator, failure
   case and independent topic. Link the source, output and reproducible checks.
4. Submit to relevant skill/plugin directories only after meeting their rules
   and obtaining any required account confirmation. GitHub publication is not
   public plugin-directory approval.
5. Share in relevant communities with clear authorship and no unsolicited bulk
   outreach, paid stars, reciprocal-star schemes or fabricated usage claims.

Possible announcement copy, to review before sending:

> I built Podcast Deep Reader because a fluent summary can hide the detail I
> needed. It turns a transcript or accessible episode link into a quick scan,
> a deep read and source evidence, with an information ledger and omission
> accounting. The repo includes an independent synthetic run, a real NASA case
> and tests. It doesn't claim lossless compression or universal link access.
> I'd especially value examples of important details it misses.

Use GitHub's available traffic and issue feedback as signals, recording the
date and data actually available. Do not infer downstream readers, installs or
retention quality from Star count alone. No automation or external messages
have been created by this plan.
